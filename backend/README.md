# BetterReads API

See [the root README](../README.md) for installation, environment variables, the temporary demo, Stripe setup, deployment and current production limitations.

Run `npm run dev` for Node's watch mode, `npm start` for the API, or `npm test` for the disposable-replica-set integration tests.

Routes:
- `/api/auth`: register, login, authenticated `GET /me`.
- `/api/books`: public catalog and detail, owner-only writes.
- `/api/users`: public profiles, allowlisted self-updates.
- `/api/wishlist`: authenticated saved books.
- `/api/offers`: private purchase and exchange proposals.
- `/api/chats`: participant-only history, messages and read markers.
- `/api/reviews`: book/reader reviews and reputation summaries.
- `/api/upload`: authenticated image upload and owned deletion.
- `/api/payments`: Stripe checkout, signature-verified raw webhook, private offer payment status.
- `/api/orders`: buyer orders, seller sales via `?view=sales`, shipping and delivery updates.
- `/health`: process health.

MongoDB must be a replica set for checkout, exchange and cancellation transactions. The API fails startup if the JWT secret is missing or too short. Cloudinary is optional for local use; Stripe checkout returns an explicit service-unavailable error when payment credentials are absent.

All prices are integer INR minor units (`priceCents` keeps the legacy API field name). A price of 25000 means ₹250. Do not submit quantities above one: each listing is a unique physical copy.


## Deploy the API on Render

The root render.yaml defines a Render Blueprint for this API. Push the file to GitHub, then in Render choose **New + / Blueprint**, connect the BetterReads repository and select the main branch. Review the service settings and create it. The Blueprint uses a free web service for a no-cost first deployment and asks for these private values in Render:

- MONGO_URI: your MongoDB Atlas connection string for the BetterReads database. Keep the database user restricted to the required database.
- CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, and CLOUDINARY_API_SECRET: Cloudinary credentials so uploaded book and profile images persist across restarts.

JWT_SECRET is generated by Render. FRONTEND_URL is the primary frontend origin used for payment redirects and is preset to https://bettereads.dvyanshu.page. FRONTEND_ORIGINS accepts a comma-separated list of additional exact origins, such as https://divyanshu026.github.io. Enter origins only, without paths or trailing slashes. PORT is provided by Render. Do not commit .env or put secrets in GitHub Actions variables.

In MongoDB Atlas, allow the Render service's outbound IP ranges under **Network Access**. Find the ranges in Render under the service's **Connect / Outbound** panel. Prefer those ranges over allowing 0.0.0.0/0; Atlas warns that /0 permits connections from anywhere. See [Atlas IP access list guidance](https://www.mongodb.com/docs/atlas/security/ip-access-list/) and [Render outbound IP ranges](https://render.com/docs/outbound-ip-addresses).

After the service deploys, open https://YOUR-SERVICE.onrender.com/health; it should return {"status":"ok"}. In GitHub, go to **Settings / Secrets and variables / Actions / Variables**, set VITE_API_URL to https://YOUR-SERVICE.onrender.com (no /api suffix), then rerun the Deploy frontend to GitHub Pages workflow. The site and API are separate deployments.

The free Render service sleeps after 15 minutes without inbound traffic and can take about a minute to wake. Its local filesystem is temporary, so Cloudinary is needed for durable uploads. Choose a paid always-on service plan in Render if cold starts are not acceptable. Stripe checkout remains disabled until STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET are configured.
